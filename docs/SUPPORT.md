# Suporte — beta fechado

O suporte do beta fechado é prestado em regime de **melhor esforço, sem SLA de resposta ou resolução**. Bugs reproduzíveis devem ser enviados pelo formulário de issue do repositório, sempre sem tokens, credenciais, dados pessoais ou dados de clientes.

Vulnerabilidades usam exclusivamente o [Security Advisory privado](https://github.com/desenvolvimentogidital-cyber/brisabase/security/advisories/new). Incidentes de uma implantação real devem seguir o runbook e a escala de plantão definidos pelo operador daquele ambiente; uma issue pública não é canal de incidente.

Antes do cadastro público, ainda devem ser publicados canal privado de suporte/privacidade, horários, idiomas, responsáveis e rota de escalonamento.

## Severidade sugerida
- **P0** — indisponibilidade ampla, perda/corrupção de dados ou incidente crítico de segurança.
- **P1** — degradação importante sem workaround aceitável.
- **P2** — falha funcional com workaround.
- **P3** — dúvida, melhoria ou problema cosmético.

SLAs de resposta/resolução só devem ser publicados quando houver capacidade operacional para cumpri-los e devem variar conforme o plano/contrato. No beta fechado, esta matriz serve para triagem e não representa compromisso contratual.
